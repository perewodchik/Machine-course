## Шаг против градиента

    ],
    reveal: "На $-\\eta \\nabla J$. Это и есть шаг градиентного спуска.",

**Градиентный спуск** повторяет шаг

$$
\theta := \theta - \eta\, \nabla J(\theta),
$$

где $\eta > 0$ — **шаг обучения**. При малом $\eta$ функция убывает: по линейному приближению $J(\theta - \eta \nabla J) \approx J(\theta) - \eta \lVert \nabla J \rVert^2$. Останавливаются, когда градиент почти нулевой. У выпуклой $J$ это глобальный минимум (урок II.5).

Для МНК $\nabla J = X^\top (X\theta - y)$, и шаг по каждому весу — правило LMS из CS229 («Linear regression», «LMS algorithm»): вес сдвигается против ошибки, умноженной на признак. Когда функцию максимизируют, например логарифм правдоподобия в логистической регрессии (CS229, «Classification and logistic regression»), шагают по градиенту: $\theta := \theta + \eta \nabla \ell(\theta)$. Это **градиентный подъём**.

<Block kind="pitfall">

Путать спуск и подъём. Минимизируем потери — минус перед $\eta \nabla J$, максимизируем правдоподобие — плюс. Перепутанный знак уводит от ответа, и тем быстрее, чем больше шаг. Проверка: после первого шага потери должны уменьшиться, а правдоподобие — вырасти.

</Block>

<Note label="По-английски">Градиентный спуск — *gradient descent*, подъём — *gradient ascent*, шаг обучения — *learning rate*.</Note>

## Шаг и порог расходимости

Слишком маленький шаг — спуск ползёт, слишком большой — перескакивает минимум. Где граница? Ответ виден на квадратичной функции $f(x) = \tfrac12 x^\top A x$ с $A \succ 0$: около минимума любая гладкая функция на неё похожа (урок II.4).

<Formula formula="f.gd-quadratic" n={1} />

В базисе собственных векторов $A$ шаг умножает каждую координату на $1 - \eta\lambda_i$. Спуск сходится, если все множители по модулю меньше единицы: $-1 < 1 - \eta\lambda_i < 1$, то есть $0 < \eta < 2/\lambda_{\max}$. Порог задаёт наибольшее собственное значение, а скорость — самый медленный множитель. При допустимом шаге множитель вдоль $\lambda_{\min}$ не меньше $1 - 2\lambda_{\min}/\lambda_{\max}$. Отношение $\kappa = \lambda_{\max} / \lambda_{\min}$ — **число обусловленности**. Чем оно больше, тем ближе этот множитель к единице и тем больше нужно шагов: у вытянутой чаши спуск идёт зигзагом.

<Note label="Игра">«Порог расходимости»: подберите наибольший шаг, при котором спуск ещё сходится, — сначала на параболе, потом на повёрнутой и вытянутой чаше. 4–6 минут. [Открыть игру](/games/divergence/)</Note>

Зачем это в ML. На «Квартирах» площадь измеряется десятками метров, а столбец единиц — единицами. Гессиан $\frac1n X^\top X$ получается сильно вытянутым. Стандартизация признака, $z = (x - \bar x)/s$, делает его круглым. Перед запуском предскажите, во сколько раз отличаются пороги шага.

<PyCode src="calculus/gd.py#data+demo" run lab="calc/apartments_gd" />

Без стандартизации порог шага — $0.00032$, а обусловленность — $91\,118$: за $20\,000$ шагов спуск так и не сошёлся. После стандартизации $\frac1n X^\top X = I$, порог равен $2$, и шаг $\eta = 1$ приходит к ответу нормальных уравнений сразу. Шаг $2.1$ выше порога, и веса уходят. ## Стохастический спуск

Полный градиент — сумма по всем $n$ объектам. При миллионах объектов один шаг стоит прохода по всей выборке. **Стохастический градиентный спуск** (SGD) шагает по градиенту одного объекта:

$$
\theta := \theta - \eta\, \bigl(\theta^\top x^{(i)} - y^{(i)}\bigr)\, x^{(i)} ,
$$

перебирая объекты в случайном порядке; проход по всем — **эпоха**. Оценка по одному объекту шумная, но в среднем равна полному градиенту (с точностью до множителя $n$). В CS229 («Linear regression») так сравнивают batch и stochastic gradient descent: стохастический начинает улучшать веса сразу, не дожидаясь прохода по выборке. **Мини-батч** — компромисс: градиент по $b$ объектам, обычно от $32$ до $512$. Перед запуском предскажите, сколько из $320$ шагов SGD увеличат потери.

<PyCode src="calculus/gd.py#data+sgd" run />

Потери выросли на $122$ шагах из $320$, но за $20$ эпох упали с $61.17$ до $0.345$, а веса пришли почти к ответу. Возле минимума шаг с постоянным $\eta$ продолжает дрожать: точнее веса станут, если уменьшать $\eta$ со временем.

<Block kind="pitfall">

Оценивать сходимость SGD по одному шагу. Отдельный шаг по случайному объекту может увеличить потери — это нормально. Смотрят на потери по всей выборке после эпохи или на скользящее среднее.

</Block>

<Note label="Игра">«Спуск в тумане»: дойдите до минимума, видя только стрелку градиента в текущей точке; на четвёртом уровне стрелка — шумная оценка, как в SGD. 4–6 минут. [Открыть игру](/games/foggy-descent/)</Note>

<Note label="По-английски">Стохастический градиентный спуск — *stochastic gradient descent*, эпоха — *epoch*, мини-батч — *mini-batch*.</Note>

## Покоординатный спуск

Иногда проще оптимизировать по одной переменной, зафиксировав остальные, — **покоординатный спуск**. Шаг — точный минимум $J$ по $\theta_j$, затем следующая координата.

<Exercise
  title="Предскажите"
  id="ii6.predict-coordinate"
  spec={{
    kind: "predict",
    prompt: "Покоординатный спуск на $f(x) = \\tfrac12 (x_1^2 + x_2^2)$ из точки $(3, 2)$: точный минимум по $x_1$, потом по $x_2$. За сколько таких шагов он придёт в минимум?",
    options: [
      { text: "За два: по одному на координату", correct: true, why: "Переменные не связаны: минимум по $x_1$ при любом $x_2$ — $x_1 = 0$, по $x_2$ — $x_2 = 0$. После двух шагов точка $(0, 0)$." },
      { text: "Никогда точно, только приближённо", why: "Так ведёт себя градиентный спуск с постоянным шагом. Здесь каждый шаг — точный минимум по координате, и для несвязанных переменных хватает одного прохода." },
      { text: "За один", why: "Первый шаг меняет только $x_1$: после него точка $(0, 2)$, и $x_2$ ещё не на месте." },
    ],
    reveal: "За два. Когда переменные связаны ($A$ не диагональна), понадобится много проходов, как зигзаг у вытянутой чаши.",
  }}
/>

Если в $\tfrac12 x^\top A x$ есть смешанное слагаемое $A_{12} x_1 x_2$, минимум по $x_1$ зависит от $x_2$, и проходов нужно много. Тот же зигзаг вдоль вытянутой чаши. Покоординатный спуск хорош, когда минимум по одной группе переменных находится точно и дёшево. Так устроен алгоритм k-средних (CS229, «Clustering and the k-means algorithm»): он по очереди минимизирует одну и ту же функцию искажения то по назначениям точек кластерам, то по центрам. Каждый шаг не увеличивает её, поэтому алгоритм сходится.

<Note label="По-английски">Покоординатный спуск — *coordinate descent*.</Note>

## Итог

- Градиентный спуск: $\theta := \theta - \eta \nabla J$; подъём для максимизации — со знаком плюс.
- На $\tfrac12 x^\top A x$ шаг умножает координаты вдоль собственных векторов на $1 - \eta\lambda_i$: сходится при $0 < \eta < 2/\lambda_{\max}$, скорость падает с ростом $\kappa = \lambda_{\max}/\lambda_{\min}$. Стандартизация признаков уменьшает $\kappa$.
- SGD шагает по одному объекту, мини-батч — по $b$; отдельный шаг может увеличить потери, судят по эпохе.
- Покоординатный спуск точно минимизирует по одной переменной за раз; k-средних — его частный случай.
