## Три выборки и оптимизм выбора

Степень полинома, $\lambda$, порог классификатора&nbsp;— **гиперпараметры**: их&nbsp;задают до&nbsp;обучения, и&nbsp;по&nbsp;обучающей ошибке их&nbsp;не&nbsp;выбрать (урок 2.2). Поэтому данные делят на&nbsp;три части: **обучающую**&nbsp;— для весов, **валидационную**&nbsp;— для гиперпараметров, **тестовую**&nbsp;— для итоговой оценки, один раз. Почему тест нельзя тратить на&nbsp;выбор? Потому что минимум из&nbsp;нескольких шумных оценок оптимистичен.

<Formula formula="f.selection-optimism" n={1} />

Каждая валидационная оценка честна сама по&nbsp;себе, но&nbsp;выбирая лучшую, мы&nbsp;выбираем и&nbsp;самый удачный шум. Чем больше вариантов перебрано, тем сильнее занижение.

<Block kind="pitfall">

«Только посмотреть» на&nbsp;тест при выборе. Как только по&nbsp;тесту принято хоть одно решение&nbsp;— степень, порог, набор признаков,&nbsp;— он&nbsp;превращается в&nbsp;валидацию, и&nbsp;итоговая оценка становится оптимистичной. Лидерборды соревнований переобучаются на&nbsp;публичную часть теста ровно по&nbsp;этой причине.

</Block>

<Note label="По-английски">Обучающая, валидационная и&nbsp;тестовая выборки&nbsp;— *train*, *validation* и&nbsp;*test sets*; гиперпараметр&nbsp;— *hyperparameter*.</Note>

## Кросс-валидация

При малом $n$ одна отложенная часть шумна и&nbsp;отнимает данные у&nbsp;обучения. **$k$-кратная кросс-валидация** делит данные на&nbsp;$k$ фолдов и&nbsp;обучает $k$ моделей: каждая учится без одного фолда и&nbsp;проверяется на&nbsp;нём.

$$
\operatorname{CV}_k = \frac1k \sum_{j=1}^{k} \operatorname{err}_j, \qquad \operatorname{SE} = \frac{s}{\sqrt k}, \quad s^2 = \frac{1}{k - 1} \sum_j (\operatorname{err}_j - \operatorname{CV}_k)^2 .
$$

SE&nbsp;— грубая оценка: обучающие части фолдов пересекаются, ошибки фолдов зависимы, и&nbsp;настоящий разброс больше. **Правило одной стандартной ошибки** берёт самую простую модель, чья средняя ошибка не&nbsp;выше минимума плюс его SE: разница меньше шума ничего не&nbsp;доказывает, а&nbsp;простая модель надёжнее. Перед тем как жать «Новое разбиение», предскажите: чей выбор степени будет прыгать сильнее&nbsp;— отложенной части или 10-кратной кросс-валидации?

<Folds n={1}>Шестьдесят квартир и&nbsp;полиномы степени 0–8. Слева&nbsp;— прогоны кросс-валидации, выделен валидационный фолд. Справа&nbsp;— ошибки фолдов по&nbsp;степеням, среднее с&nbsp;полосой $\pm$SE и&nbsp;ошибка одной отложенной части. Внизу&nbsp;— стратификация звонков с&nbsp;редкими откликами.</Folds>

Выбор по&nbsp;отложенной части меняется от&nbsp;разбиения к&nbsp;разбиению, по&nbsp;10-кратной кросс-валидации&nbsp;— заметно реже. При редком классе простое разбиение может оставить фолд вообще без положительных; **стратификация** раскладывает каждый класс по&nbsp;фолдам отдельно, и&nbsp;доля положительных в&nbsp;каждом&nbsp;— как во&nbsp;всей выборке.

## Всё обучение — внутри фолда

Масштабирование, заполнение пропусков, отбор признаков, подбор порога&nbsp;— всё это обучение, и&nbsp;его&nbsp;повторяют внутри каждого фолда. В&nbsp;scikit-learn это делает `Pipeline`: `cross_val_score(make_pipeline(StandardScaler(), Ridge()), X, y)` заново считает средние и&nbsp;разбросы на&nbsp;каждой обучающей части. А&nbsp;чтобы честно оценить всю процедуру выбора вместе с&nbsp;перебором гиперпараметров, нужна **вложенная кросс-валидация**: внешний цикл оценивает, внутренний (`GridSearchCV`) выбирает, и&nbsp;внешние валидационные фолды во&nbsp;выборе не&nbsp;участвуют.

Крайний случай&nbsp;— «без одного» ($k = n$): каждая модель учится почти на&nbsp;всех данных, но&nbsp;обучений $n$. Для гребневой регрессии их&nbsp;можно не&nbsp;делать вовсе.

<Block kind="pitfall">

Масштабировать, заполнять пропуски или отбирать признаки по&nbsp;всей выборке до&nbsp;кросс-валидации, отчитываться минимальной ошибкой кросс-валидации как ожидаемой ошибкой на&nbsp;новых данных, делить без стратификации при редком классе. Все три ошибки делают оценку оптимистичной.

</Block>

<Note label="По-английски">Вложенная кросс-валидация&nbsp;— *nested cross-validation*, «без одного»&nbsp;— *leave-one-out (LOO)*, конвейер&nbsp;— *pipeline*.</Note>

## Итог

- Обучение подбирает веса, валидация&nbsp;— гиперпараметры, тест&nbsp;— итоговую оценку, один раз. Минимум валидационных ошибок оптимистичен.
- $k$-кратная кросс-валидация: среднее ошибок фолдов и&nbsp;грубая SE $= s/\sqrt k$; правило одной SE берёт самую простую модель в&nbsp;пределах SE от&nbsp;лучшей; при редком классе фолды стратифицируют.
- Вся предобработка и&nbsp;отбор признаков&nbsp;— внутри фолда (`Pipeline`); оценку процедуры выбора даёт вложенная кросс-валидация.
