Метрики классификации: порог, ROC, PR, калибровка

В CS229
В конспекте этой темы нет: метрики и выбор порога разбирают на лекции ML advice. Без них модель нельзя отдавать в работу.

Модель выдаёт вероятность, а решение принимает порог. Выберем порог по цене ошибок и увидим, почему доля верных ответов здесь обманывает.

Около 50 минут: четыре цикла, восемь вопросов и задача «Цена ошибки».
Опирается на
  • Условная вероятность математика, III.2
  • Риск и кросс-валидация математика, IV.7

Порог превращает вероятность в решение

Банк рассматривает 300 заявок на кредит. Модель из урока 1.4 выдаёт для каждой заявки вероятность дефолта \(\sc\). Решений два: выдать кредит или отказать. Правило с порогом \(\thr\) отказывает, если вероятность не меньше порога:

$$\hat\y = 1\{\sc \ge \thr\}.$$
Честные вероятности
Здесь модель откалибрована: среди заявок с \(\sc \approx 0.2\) дефолтов около 20%. Как это проверить, разберём в цикле 4.

В выборке 84 дефолта из 300, то есть 28%. Если выдавать кредит всем, решение будет верным в 72% случаев.

Сначала предскажите. С порогом 0.5 модель права в 80% случаев, а правило «выдавать всем» — в 72%. Значит, порог 0.5 — хороший выбор?

Матрица ошибок раскладывает 300 решений на четыре клетки. Ошибок два вида: лишний отказ (ложноположительный, FP) и пропущенный дефолт (ложноотрицательный, FN). Две главные доли:

$$\text{precision} = \frac{TP}{TP + FP}, \qquad \text{recall} = \frac{TP}{TP + FN}.$$
Термины
Precision — «точность»: доля дефолтов среди отказов. Recall — «полнота»: доля пойманных дефолтов. Не путайте точность с долей верных ответов (accuracy).

Проверка. Порог подняли с 0.5 до 0.7. Что произойдёт с точностью и полнотой?

ROC и цена ошибок

Каждый порог даёт точку: доля ложных отказов по горизонтали, полнота по вертикали. Все пороги вместе — ROC-кривая. Площадь под ней (AUC) равна 0.848: с такой вероятностью случайный дефолт получает оценку выше, чем случайный вернувший кредит. AUC не зависит от порога, поэтому порог она не выбирает.

Задача «Цена ошибки». Найдите порог, при котором цена ошибок минимальна. Можно двигать ползунок, а можно посчитать.

Отказ выгоден, если ожидаемая потеря от выдачи \(5\sc\) больше потери от отказа \(1 \cdot (1 - \sc)\).

Почему 1/6
Для честных вероятностей отказ выгоден, когда \(5\sc > 1 - \sc\), то есть \(\sc > 1/6 \approx 0.167\). В общем виде \(\thr^\star = \dfrac{c_{FP}}{c_{FP} + c_{FN}}\).

Типичная ошибка. Подбирать порог на тестовой выборке. Порог — такой же параметр, как веса: его выбирают на валидации, а тест открывают один раз.

В коде

Те же 300 заявок. Перебираем пороги и сравниваем лучший с теоретическим.

Pythonвыполняется в браузере Открыть в Colab 
import numpy as np
from ml_basics.threshold import make_scores

p, y = make_scores()   # те же 300 заявок, что на рисунках

def total_cost(p, y, t, c_fp=1, c_fn=5):
    reject = p >= t
    fp = np.sum(reject & (y == 0))   # лишние отказы
    fn = np.sum(~reject & (y == 1))  # пропущенные дефолты
    return c_fp * fp + c_fn * fn

thresholds = np.append(np.unique(p), 1.001)
costs = [total_cost(p, y, t) for t in thresholds]
best = thresholds[np.argmin(costs)]
print("лучший порог:", best, "цена:", min(costs))
print("теория 1/6:", total_cost(p, y, 1 / 6), " порог 0.5:", total_cost(p, y, 0.5))
