# Новый урок

Перед началом прочитай:
- `docs/conventions/pedagogy.md` — анатомия урока (циклы, проверки, уровни усвоения);
- `docs/conventions/authoring.md` — тон, типографика, блоки, нумерация;
- `docs/conventions/notation.md` — обозначения;
- карточку урока в `docs/program/<модуль>.md` — цели, понятия, формулы, типичные ошибки, практика.

## Шаги

1. **Найди урок в программе.** Номер, slug и порядок уже есть в `content/courses/foundations/<модуль>/module.yaml`. Если урока там нет — сначала добавь его туда и в `docs/program/`.
2. **Проверь граф.** Все понятия из «Опирается на» существуют в `content/concepts/*.yaml`. Новые понятия добавь с `prerequisites`, `lesson`, `cs229` (издание + название раздела).
3. **Спланируй 2–4 цикла по 7–12 минут.** Каждый цикл: попытка или предсказание → исследование (виджет или пример) → название и определение → вывод или правило → проверка. Запиши план списком в начале файла, как комментарий.
4. **Напиши MDX** (`<slug>.mdx`): frontmatter (`id`, `title`, `number`, `concepts`, `minutes`), затем циклы. Компоненты передаются сайтом, импорты в MDX не пиши. Формулы с ролями — только из реестра (`<Formula formula="f.…">`) или через `\sym{…}{…}`.
5. **Формулы и выводы** оформляй скиллом `new-formula`: каждый шаг с численной проверкой.
6. **Практика:** минимум одна проверка в каждом цикле, итоговые упражнения (параметрические, с разбором неверных вариантов), ссылка на игру или лабораторную, если она есть в программе.
7. **Заметки на полях:** английский термин при первом появлении, раздел CS229, пометки учителя у типичных ошибок.
8. **Проверь** скиллом `content-review` и запусти `cd code && pytest`.

## Чего не делать

- Не копировать текст и рисунки из материалов Stanford и других курсов.
- Не писать урок «стеной текста»: больше 5 минут чтения без вопроса — ошибка.
- Не вводить понятие, которого нет в графе, и не ссылаться на урок, который идёт позже, без пометки «забегая вперёд».
