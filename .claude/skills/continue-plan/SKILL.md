# Продолжить работу по плану

Цель — сделать одну задачу (или несколько, если попросили) так, чтобы следующий агент начал с нужного места, не читая лишнего.

## 1. Сориентироваться (не больше трёх файлов)

1. `docs/implementation/context/00-project.md` — целиком (одна страница).
2. `docs/implementation/PLAN.md` — только блок «Сейчас» и задачу из него. Найти задачу Grep'ом по ID (`### S1.03.`), не читать план целиком.
3. `docs/implementation/LOG.md` — только верхнюю запись (до первой строки `---` после шаблона).

Проверить ветку: работаем в `impl/stage-<N>`. Если её нет — создать от ветки, где лежит `docs/implementation/` (`main`, если план там; иначе `origin/docs/course-analysis`).

## 2. Выбрать задачу

- Если пользователь назвал задачу — её (проверив зависимости).
- Иначе первая `[~]`; если таких нет — первая `[ ]`, у которой все зависимости `[x]`. Задачи `[!]` и `[u]` пропустить.
- Для блоков уроков (`S3.L1` и т. п.) задача — первый неотмеченный урок `L-*` в списке.
- Поставить `[~]`, обновить блок «Сейчас» (задача, дата).

## 3. Загрузить контекст

- Прочитать пакеты из поля «Контекст» задачи (`docs/implementation/context/*.md`).
- Полные документы — только по ссылкам из пакета и только нужный раздел (Grep по заголовку).
- Для урока — только его карточку: Grep `### <номер>.` в `docs/program/`.
- Широкий поиск по коду — через субагента `Explore`.
- Если для задачи нужен навык из скилла (`new-lesson`, `new-formula`, `new-widget`, `new-game`, `new-notebook`, `frontend-design`, `design-critique`, `accessibility-review`, `content-review`) — загрузить скилл.

## 4. Сделать

- Держаться поля «Сделать» и критериев «Готово, когда». Если план неверен или устарел — сделать разумно и записать отклонение в журнал, а не молча.
- Соблюдать `CLAUDE.md` (правила 1–7).
- Не расширять задачу: заметил другое — добавить задачу в план (формат как у соседних) или пункт в журнал.

## 5. Проверить

- Все команды из поля «Проверка» и из `context/testing-ci.md` для затронутых частей. Вывод обрезать (`| tail -20`).
- Интерфейс: скриншоты Playwright (1440 и 390 px, обе темы, поля показаны и скрыты) → скиллы `design-critique` и `accessibility-review`; исправить критичное.
- Без зелёных проверок задача не `[x]`.

## 6. Отметить и записать

1. В `PLAN.md`: статус `[x]` (или `[~]`, `[!]`, `[u]`), поле «Итог» — 1–3 строки: что сделано, коммит.
2. Блок «Сейчас»: следующая задача, дата, короткая фраза.
3. `LOG.md`: новая запись **сверху** (под шаблоном) по шаблону; не длиннее 12 строк; для `[~]` — «Где остановился».
4. Коммит с ID задачи (`S1.03: …`), пуш в `impl/stage-<N>` (`git push -u origin impl/stage-<N>`).

## 7. Остановиться и отчитаться

- По умолчанию — после одной задачи. Если попросили несколько — повторить шаги 2–6.
- Отчёт пользователю: что сделано, как проверено (команды и результат), что дальше, вопросы.
- Нужна помощь пользователя (доступ, деньги, решение, люди) — статус `[u]`, вопрос в журнал и в отчёт; не обходить.
