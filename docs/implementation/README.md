# Как устроена реализация

Курс реализуют агенты Claude Code (и люди) по одному плану. Эта папка — всё, что нужно, чтобы начать с любого места и не тратить контекст на лишнее.

| Файл | Зачем | Кто пишет |
|---|---|---|
| [`PLAN.md`](PLAN.md) | Этапы и задачи со статусами; блок «Сейчас» — где мы | Агент обновляет статусы, «Итог», «Сейчас» |
| [`LOG.md`](LOG.md) | Журнал: что сделано, где остановились, вопросы (новое сверху) | Агент добавляет запись после каждой задачи |
| [`context/`](context) | Пакеты контекста: выжимки по областям на 1–2 страницы со ссылками на полные документы | Обновляет тот, кто меняет правила области |
| [`KICKOFF.md`](KICKOFF.md) | Стартовые промпты для новой сессии | — |
| `.claude/skills/continue-plan/` | Порядок работы агента по плану | — |

## Как агент работает

1. Читает `context/00-project.md` (одна страница), блок «Сейчас» в `PLAN.md` и верхнюю запись `LOG.md`.
2. Берёт задачу: сначала `[~]`, иначе первую `[ ]` с выполненными зависимостями. `[!]` и `[u]` пропускает.
3. Читает **только** пакеты из поля «Контекст» задачи. Полные документы — только по ссылке из пакета и только нужный раздел.
4. Делает задачу, проверяет командами из поля «Проверка».
5. Отмечает статус, пишет «Итог» (1–3 строки), обновляет «Сейчас», добавляет запись в `LOG.md`, коммитит с ID задачи (`S1.03: …`) и пушит в ветку этапа.

## Статусы

| Метка | Значение |
|---|---|
| `[ ]` | не начата |
| `[~]` | в работе (в журнале — где остановились) |
| `[x]` | готова (проверки пройдены) |
| `[!]` | заблокирована (причина — в «Итоге» и журнале) |
| `[u]` | нужен пользователь (решение, доступ, люди для пилота) |

## Гигиена контекста

- Не читать целиком `docs/analysis.md`, `docs/program/*`, `docs/conventions/*`: в пакетах контекста есть выжимки и точные ссылки на разделы.
- Карточку урока искать Grep'ом по `### <номер>.` и читать только её.
- Для широкого поиска по коду — субагент `Explore`, а не чтение десятков файлов.
- Длинные выводы команд обрезать (`| tail -20`); скриншоты смотреть по одному.
- Не копировать в журнал логи и диффы: только итог и команды проверки.

## Ветки и коммиты

- Ветка на этап: `impl/stage-1`, `impl/stage-2`, … Создаётся от ветки, где лежит эта папка: сейчас — `docs/course-analysis`, после слияния в `main` — `main`. Рекомендуем влить `docs/course-analysis` в `main` до начала этапа 1, чтобы ветки этапов шли от `main`. Команды — в скилле `continue-plan`, шаг 1.
- Коммит на задачу (или на урок): `S1.03: add tokens, Tailwind theme and fonts` — ID, двоеточие, повелительное предложение по-английски, заголовок ≤ 72 знаков; в конце — строки авторства, если их требует среда.
- Pull request ветки этапа в `main` — последняя задача этапа (S1.14, S2.12): агент спрашивает пользователя и открывает PR после согласия.

## Как добавить задачу

Скопировать формат существующей: ID (`S<этап>.<номер>`), статус, зависимости, контекст (1–3 пакета), «Сделать», «Готово, когда» (проверяемые критерии), «Проверка» (команды), «Итог». Если для задачи нет подходящего пакета — сначала создать пакет в `context/` (до 2 страниц).
