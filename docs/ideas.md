# Что даёт компьютер: идеи

Бумажный учебник не умеет проверять каждую строку решения, бесконечно генерировать задачи, помнить, что ученик забывает, и показывать формулу, график и код как одно целое. Ниже — идеи, которые используют это, с приоритетом и местом в плане (`docs/implementation/PLAN.md`).

Главное преимущество курса — **формулы как данные с численной проверкой** (`content/formulas`, `code/mlf/formulas.py`). Многие идеи ниже стоят на нём, и у конкурентов их нет.

## Принципы

- Компьютер **проверяет и подсказывает**, а не решает за ученика.
- Каждая «плюшка» должна **учить**, а не развлекать: если её можно убрать без потери в усвоении — убираем.
- **Без** очков опыта, бейджей и серий дней: они дают тревогу и «фарм», а не знания (см. `docs/conventions/games.md`).
- Все утверждения машины о математике **проверяются численно** — и у ИИ-тьютора тоже.

## A. Сделать в первую очередь (этапы 2–3)

Высокая ценность, опора на то, что уже есть.

### A1. Проверка вывода ученика по шагам

Ученик сам пишет вывод строка за строкой (ввод формул — MathLive). Курс переводит каждую строку в выражение (Compute Engine) и проверяет её тем же способом, что и наши выводы в CI: подставляет случайные матрицы нужных размеров и сравнивает со строкой выше. Ошибку видно сразу и точно: «шаг 3 не равен шагу 2; похоже, транспонирование без смены порядка».

- **Почему учит:** немедленная обратная связь на уровне шага; ученик пишет сам, а не узнаёт готовое.
- **Как:** харнесс проверки на TypeScript (или Pyodide) поверх `symbols` и `shape` из реестра; MathLive + Compute Engine для разбора TeX.
- **План:** S3.03, S3.04.

### A2. Диагноз ошибки по ответу

Для каждого правила в реестре описываем типичные «мутации»: забыть транспонирование, переставить множители, потерять $\tfrac12$, делить на $n$ вместо $n-1$, перепутать $\sigma$ и $\sigma^2$. Курс считает ответы, которые дают эти мутации, и сравнивает с ответом ученика: «похоже, вы сложили $\theta^\top X^\top y$ и $y^\top X \theta$ как разные слагаемые».

- **Почему учит:** обратная связь называет конкретное заблуждение, а не «неверно».
- **Как:** поле `mutations` у правил (выражение NumPy с ошибкой); те же мутации — неверные варианты в задачах с выбором.
- **План:** S3.05.

### A3. Бесконечная практика

Каждая задача — генератор с seed: новые числа при каждой попытке, ответ считает код. Кнопка «Ещё задача» даёт новую задачу того же типа; итоговая проверка модуля — перемешанный набор.

- **Почему учит:** извлечение из памяти и перемешивание задач.
- Интервальных повторений нет — сняты решением заказчика 14.10.2026.
- **План:** S2.03.

### A4. Живые числа в тексте

Число в предложении можно потянуть мышью: «при шаге $\eta = 0.1$ спуск сходится за 37 шагов» — меняем $\eta$, и число шагов, график и вывод пересчитываются.

- **Почему учит:** связь «параметр → следствие» видна без отдельного виджета.
- **Как:** компонент `<Scrub>` поверх модели виджета; клавиатура — стрелки.
- **План:** S2.01 (в `_kit`).

### A5. Связанные представления

Формула, рисунок, код и числа — одно целое: наведение на $\theta$ подсвечивает его везде; изменение в ячейке кода перерисовывает рисунок; ползунок рисунка меняет числа в формуле.

- **Почему учит:** перевод между представлениями — главный навык в чтении CS229.
- **Как:** атом подсветки (nanostores) уже заложен; обмен состоянием «Python ↔ виджет» через протокол воркера.
- **План:** S1.07, S2.02, S2.05.

### A6. Размерности в реальном времени

В ячейке кода и в поле ввода формулы рядом с выражением видна его форма: `X.T @ X @ theta  →  (d,)`. Несогласованные размерности подсвечиваются до запуска.

- **Почему учит:** ошибки форм — главная практическая ловушка в NumPy и в матричном анализе.
- **Как:** для формул — по `shape` из реестра; для кода — запуск на маленьких массивах в Pyodide и вывод форм промежуточных выражений.
- **План:** S3.06.

### A7. Граф понятий как навигатор

Карта курса показывает пройденные уроки; у каждого понятия — путь «зачем это мне» до раздела CS229. Ошибка в задаче предлагает короткую справку по пререквизиту, на котором она, вероятно, основана.

- **План:** S3.02, S2.04.

## B. Следующий слой (этапы 3–5)

### B1. ИИ-тьютор, привязанный к уроку

Claude через API знает текущий урок, формулу и шаг. Он даёт подсказки лесенкой (идея → план → часть решения), объясняет «почему» шага, разбирает самообъяснение ученика по рубрике. Он не выдаёт ответ первым и проверяет свои математические утверждения инструментом — нашим численным харнессом, а не «на глаз».

- **Почему учит:** персональная обратная связь там, где автор не предусмотрел вопрос.
- **Риски:** первый сервер в проекте (прокси к API, ключ не в браузере), расходы, приватность. **[решить]** — `docs/analysis.md` §9.
- **Как:** контекст — только из нашего контента (реестр формул, карточка урока, типичные ошибки); выбор модели и параметров — при реализации, по скиллу `claude-api`.
- **План:** этап 6.

### B2. «Научи робота»

ИИ играет ученика, который делает типичную ошибку; задача человека — найти ошибку и объяснить её. Эффект «обучения через объяснение» сильнее простого решения задач.

- **План:** этап 6, после B1.

### B3. Компаньон к конспекту CS229

Для каждого раздела конспекта (по названию): чек-лист уроков-пререквизитов с галочками пройденных, наши карточки формул на каждый шаг вывода, пятиминутная разминка перед чтением. Ученик читает оригинальный PDF рядом; текст Stanford не копируется.

- **План:** S5.03.

### B4. Лаборатории-симуляции

ЦПТ, закон больших чисел, смещение и разброс оценок, кросс-валидация — тысячи повторений в браузере за секунду; ученик меняет условия эксперимента и предсказывает исход до запуска.

- **План:** уроки III.8, IV.2, IV.7 (этап 4).

### B5. Проверка кода свойствами

Скрытые тесты лабораторных дополняются property-based проверками (Hypothesis в Pyodide): «ваша функция ломается при $n = 1$» вместо «тест 7 не пройден».

- **План:** S3.07.

### B6. Калибровка уверенности

Перед ответом ученик отмечает уверенность; курс показывает график калибровки («когда вы уверены на 90%, вы правы в 70% случаев»).

- **План:** S2.03 (сбор), S4.x (отчёт).

### B7. Шпаргалки по пройденным урокам

Печатная страница по модулю или разделу CS229 из пройденных уроков, с формулами и типичными ошибками. Собирается из реестров автоматически.

- **План:** S5.04.

### B8. Аналитика для автора

Трудность и различающая способность заданий, частота каждого неверного варианта, шаг вывода, на котором застревают, кривые обучения по понятию. Это петля улучшения контента.

- **План:** S2.10 (сбор без бэкенда), этап 6 (сервер).

## C. Эксперименты (позже, по результатам пилота)

- **C1. Генерация задач языковой моделью** с обязательной численной проверкой и ревью автора — расширение банков.
- **C2. Рукописный ввод формул** на планшете.
- **C3. 3D-визуализации** (собственные векторы в $\mathbb{R}^3$, PCA) с ленивой загрузкой.
- **C4. Офлайн-режим (PWA)** для чтения уроков без сети.
- **C5. Голосовые объяснения** вывода по шагам (озвучка `note` и `why`).

## Чего не делаем

- Очки, бейджи, серии дней, таблицы лидеров.
- ИИ, который решает за ученика или пишет ему код.
- Анимации и «вау-эффекты», которые не объясняют математику.
- Сбор данных без согласия; продажа и передача данных.
