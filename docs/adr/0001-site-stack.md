# 0001. Стек сайта

- Статус: предложено (ждёт ответов из `docs/analysis.md` §9)
- Дата: 2026-10-14

## Контекст

Курс — в основном статичный текст с формулами и точечным интерактивом (виджеты, игры, Python). Нужны типизированный контент (граф понятий, формулы как данные), быстрая загрузка без JS на уроках без виджетов и доступность. Версии сверены с npm 14.10.2026: Astro 7.3.8, Tailwind CSS 4.3.3, Base UI 1.9.0, KaTeX 0.19.0.

## Решение

- Astro 7.3 + MDX, статическая сборка; коллекции контента со схемами Zod 4.
- React 19 только в островах (виджеты, игры, Python). Педагогические компоненты (`Formula`, `Derivation`, `Prereqs`, `Sidenote`) — `.astro` и скрипты без фреймворка.
- Tailwind CSS 4.3 с `@theme` из токенов курса; дефолтные палитра, тени, скругления и шрифты отключены (`theme.css` проверен компиляцией).
- Примитивы в островах — Base UI через shadcn/ui; на статичных страницах — нативные `popover` с CSS anchor positioning и `<details>`.
- KaTeX 0.19 при сборке; `trust` разрешает только `\htmlData` и `\htmlClass`, `strict` — функция; символы с ролями — макрос `\sym`.
- Markdown-конвейер: на срезе — явный `unified()` (`@astrojs/markdown-remark`), логика KaTeX, `\sym` и Typograf — в модуле, не зависящем от процессора, чтобы позже перейти на Sätteri.
- Визуализации — свой SVG-слой на d3-scale (`widgets/_kit`); Mafs сравнить на срезе.

## Последствия

- Урок без виджетов отдаёт 0 KB React.
- Нужен валидатор контента (граф без циклов, ID, компиляция KaTeX, `\sym` у символов с ролями).
- Подсветка символов между островами — через атом nanostores и делегирование событий.

## Отвергнутые варианты

- Next.js + Fumadocs: удобнее для аккаунтов и серверной логики, но для статичного курса тяжелее и слабее в типизации контента.
- Starlight, Docusaurus: узнаваемый вид документации, с темой пришлось бы бороться.
- Radix напрямую: shadcn/ui с июля 2026 по умолчанию ставит Base UI; Radix развивается медленнее.
- MathJax: сильнее озвучка, но тяжелее; MathML от KaTeX покрывает базовую доступность.
